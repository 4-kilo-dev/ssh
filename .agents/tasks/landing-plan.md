# Implementation Plan

## Findings and decisions

- The web landing route is `app/[[...slug]]/page.tsx` → `components/PageRouter.tsx` → `components/LandingPage.tsx`; `PageRouter` returns `<LandingPage />` only for `pathname === "/"`. The current page already has hero, area strip, featured venues, booking-next-step, and a closed all-venues disclosure.
- The Telegram landing route is `app/tg/[[...slug]]/page.tsx` → `components/tg/TgPageRouter.tsx` → `components/tg/TgHome.tsx`; it is intentionally a compact, separate phone-first home rather than a direct render of `LandingPage`. `app/tg/layout.tsx` mounts `NavBaseProvider base="/tg"` and `TgShell`, so shared `components/CoreFlow.tsx`/`VenueCard` links are automatically prefixed for Telegram while the web shell is skipped by `components/AppShell.tsx`.
- Asset inventory: `public/brand-mark.svg` exists and `public/assets/` does not exist. The exact files under `public/images/` are `landing-hero.svg`, `vendor-beauty-1.svg`, `vendor-beauty-2.svg`, `vendor-beauty-3.svg`, `vendor-catering-1.svg`, `vendor-catering-2.svg`, `vendor-catering-3.svg`, `vendor-decor-1.svg`, `vendor-decor-2.svg`, `vendor-decor-3.svg`, `vendor-generic-1.svg`, `vendor-generic-2.svg`, `vendor-generic-3.svg`, `vendor-music-sound-1.svg`, `vendor-music-sound-2.svg`, `vendor-music-sound-3.svg`, `vendor-photography-1.svg`, `vendor-photography-2.svg`, `vendor-photography-3.svg`, `venue-ballroom.svg`, `venue-conference.svg`, `venue-garden.svg`, `venue-generic.svg`, and `venue-wedding-hall.svg`. None is the requested bright outdoor wedding/event-stage image. `landing-hero.svg` is explicitly a dark “PLACEHOLDER HERO IMAGE”; `venue-garden.svg` is the closest semantic local fallback, but it is also only a placeholder and must not be presented as the attached photograph.
- Chosen hero path: `/images/addis-wedding-stage-hero.jpg`, added from the user-provided attachment without fetching or hotlinking a remote image. Until that local file is available, the UI must fall back to `/images/venue-garden.svg` through the existing local-image convention. `lib/images.ts` remains the single source of truth so the web and Mini App do not develop separate asset paths.
- Reuse `app/tokens.css` values (`--ink`, `--muted`, `--paper`, `--surface`, `--line`, `--teal`, `--teal-dark`, `--teal-soft` and status colors) rather than introducing a second palette. Reuse `.btn`, `.btn-primary`, `.btn-secondary`, `.card`, `.featured-card`, `.venue-card`, `.eyebrow`, `.text-link`, `VenueCard`, `useDemo`, `formatETB`, `formatNumber`, `t`, and `Link` from `@/lib/nav`. Do not change token values: `globals.css` imports them for both surfaces and `app/tg/tg.css` is scoped to Mini App classes.
- The visual direction is a warm Addis celebration marketplace: the attached white floral canopy/gold accents/red aisle image should provide the visual focal point, with concise Addis Ababa/Ethiopia-oriented copy, strong teal/gold-adjacent accents that retain contrast, and direct “Explore venues” and “Book a venue” actions. Keep all routes, local demo state, bilingual behavior, vendor/admin links, and the Telegram navigation contract intact.
- Repository guidance found: no `AGENTS.md`, `CONTRIBUTING.md`, or `.kiro/steering` files are present. The README commands are `pnpm dev`, `pnpm typecheck`, and `pnpm build`; browser suites are external to `package.json` and run against an already-started server with `node tests/e2e/images.mjs`, `node tests/e2e/mini-app.mjs`, and `node tests/e2e/web-routes.mjs`.
